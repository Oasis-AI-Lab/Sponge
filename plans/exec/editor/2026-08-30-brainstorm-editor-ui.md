## 一、发散

### 轴 A：共享顶栏意味着什么（窗口模型）

| 候选 | 含义 | 代价 |
|---|---|---|
| **A1 顶栏为 frame 级 chrome** | 两个模式共享一条顶栏（模式切换 + 容器状态），需新增 frame 级 top bar 槽 | **壳改动 > D-O 批准的 12 行**——触碰"借壳边界" |
| A2 顶栏只是视觉统一 | 各页面自绘，仅样式对齐 | 成本低；但"共享"名不副实 |
| A3 顶栏 = 容器状态条 | 常驻显示居民/域/模式切换，成为容器的 chrome | 概念最贴（容器常驻 chrome）；改动最大 |

〔假设〕接触面：`shell.page` / `sponge.portal.nav`（可能被顶栏吞掉）/ 路由 store（一个还是两个）/ **D-O 的"最小改壳"边界需重新确认**。
〔假设〕概念影响：若顶栏共享，则"**两个窗口**"变成"**一个壳的两个模式**"——07 的"容器两个窗口"表述需相应调整。

### 轴 B：画板是什么的画布

| 候选 | 内容 | 判断依据 |
|---|---|---|
| **B1 结构画布** | 切片/元素/依赖的拓扑图 | 最贴 Sponge 本体（切片=结构） |
| B2 流程画布 | pipeline 节点+连线（Dify/n8n 式） | 调研：画布红海；且非 Sponge 差异 |
| B3 语义画板（Glora） | 组件 + 连线 + **不可见层** + 运算域 | 笔记现成心智；Glora 本就可被别的框架承载 |
| **B4 混合**：结构画布 + 运算域交互 | 拓扑 + 框选→运算→固化 | 与"运算域=瞬态域"定案一致 |

〔假设〕关键问：画板是"编辑器的一种**视图**"，还是"编辑器的**本体交互形态**"？（07："结构编辑不是文本编辑"——画板正是结构编辑的自然形态。）

### 轴 C：难点拆解（"非常难搞"具体难在哪）

| # | 难点 | 说明 |
|---|---|---|
| C1 | **投影层** | 自由容器（untyped）→ 具体观感（每个 kind 长什么样）——07 自认最难的工程 |
| C2 | **布局** | 无 schema 的任意结构如何自动布局（树？力导？自由摆放？） |
| C3 | **三向同步** | 画板 ↔ 文件（S1′ 格式）↔ 运行态——三者一致 |
| C4 | **交互原语** | 选择/多选/框选/连线/分组/**嵌套**——自由容器不允许预设交互集 |
| C5 | **数据现实** | core 未实现 → 画板对什么操作？（桩/派生/文件） |
| C6 | 渲染与性能 | 大图的渲染与交互 |
| C7 | **心流** | 07 公理：结构编辑做到心流 ≈ 可视化编程圣杯 |
| **C8** | **地基缺失（新发现）** | 栈里无画布/图库，且**禁组件库** → 手写 DOM/SVG，或提**政策例外**（引 React Flow 类依赖） |

### 轴 D：prototype 的性质

| 候选 | 含义 | 风险 |
|---|---|---|
| **D1 一次性原型**（可丢） | 只验证"交互 + 投影"假设；允许丑、允许桩数据 | 快、便宜；但产出不进入产品 |
| D2 产品起点 | 直接长成 S2 画布 | 与调研排序冲突；沉没成本高 |

## 二、张力清单

| # | 张力 | 检验/化解方式 |
|---|---|---|
| T1 | **共享顶栏 vs D-O"最小改壳"** | 若顶栏需 frame 级槽 → 壳改动超 12 行 → 回到战略层重新批准借壳边界 |
| T2 | **画板 prototype vs 调研排序（S1′→S3→S2）** | 先做最难最红的一项（画板最快暴露"结构编辑能否成立"，但推迟可交付）；反之文件级先可交付。**这是取舍不是对错** |
| T3 | **无画布地基 + 禁组件库 vs "画板即原型"** | 要么手写（DOM/SVG）、要么政策例外——**必须先定，否则 prototype 无法开工** |
| T4 | **画板对什么操作 vs core 未实现** | 原型期长期对桩 → 触碰"数据源诚实"原则（必须显示 source 判别器） |
| T5 | **顶栏共享 vs 两个窗口的概念** | "两个窗口"是否降级为"一个壳两个模式"？影响 07 的表述与 Portal 的导航设计 |

## 三、边界收敛提案（待战略层确认）

**IN（本轮 Editor UI 的范围）**

1. **顶栏模型定案**：共享顶栏的层级（frame 级 / 页面级）与两模式切换方式（决定壳改动量）；
2. **画板 prototype**：最小结构画布——节点 + 连线 + 选择 + **一个结构操作**（如"新增/连接一个切片"）；含 **1–2 种 kind 的投影**（验证投影层假设）；
3. **画板地基决策**：手写（DOM/SVG）vs 依赖例外（引图库）；
4. **与 Portal 的模式切换**：共享顶栏下的两模式导航与路由；
5. **最小双向同步**：画板 ↔ 文件（S1′ 的最小格式）——若 D1 可丢，此项可降级为"导出快照"。

**OUT（本轮明确不做）**

- ❌ 全 kind 投影、全交互集（框选/分组/嵌套/多选连线）
- ❌ 运算域交互（框选→运算→固化）——**待定**：可作为 prototype 的"那一个结构操作"候选
- ❌ agent 工具面（S3）
- ❌ 真实 core 数据（用桩/派生，且必须显示 source）
- ❌ 性能优化、协同编辑、后端持久化
- ❌ Editor 的完整 S2/S3/S4
