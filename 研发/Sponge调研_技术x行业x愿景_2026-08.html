技术结论

C3「调度驱动」是唯一真正的护城河，但护城河的形状必须改写

先说被打脸的部分：编排、主动释放、演化三件事在 2026 年都已有成熟的业界对应物。LangGraph 的 ServerRuntime 支持每次运行重建图、Command 类型实现无边缘动态跳转 S；主动释放已有 ProAct（idle-time compute + 投递策略）S、企业 Context Graph（Precision@5 = 0.83，关键信息浮现时间 47 分钟 → <30 秒）A；演化已经是一个有完整分类学的学术领域（五类演化对象 / 四类图重写）S。Sponge 打不赢「机制独占」。

能赢的是三者的单一调度闭环 + 调度器自身可替换：业界把这三者放在三个不同层（框架层 / 产品层 / 模型层），没有任何系统让它们共用同一份结构化状态、由同一个可替换内核驱动。护城河从「机制」降级为「组合与耦合」——这不是坏事，它是更诚实、也更可检验的护城河。

补充：C4 已彻底沦为行业共识（MCP / Agent Skills / Agent Plugins 1.0 / DeepSeek Harness「一切即插件」），不再是差异点；C5 已被 DeepSeek Harness 的 4-preset 体系产品化实现，成立但同样不是差异点。真正空白的是 C2 的「自由容器」抽象与 C3 的组合。

行业结论

市场在爆炸，种子轮在死：钱从「模型层」转向「编排与打包层」，但只对已成型者开放

2026 Q1 全球 VC 3,000 亿美元（同比 +150%），AI 占 81%；但 OpenAI/Anthropic/xAI/Waymo 四家就拿走 1,880 亿（62%）。剔除 10 笔以上 10 亿美元级轮次后，消费与企业 AI 全季仅剩 175 亿 A。最刺眼的数字：2026 Q1 全季度新成立的 agentic AI 创业公司只有 1 家（2023 全年 245 家）A。

资本正从模型层转向编排基础设施（MCP 服务器 Q2 2026 突破 9,400 个，环比 +58%A），但转向的是「打包与分发标准」这一已经有人占位的地方：2026-08-06 六家巨头（OpenAI/Microsoft/GitHub/AWS/Vercel/Anysphere）发布 Agent Plugins 1.0，Google 当天加入核心维护者 S。

采用侧同样分裂：80% 企业至少一个生产应用含 agent（2024 年仅 33%）A，但只有 21% 组织有成熟的自治 agent 治理模型 A，且 Gartner 预测 >40% 的 agentic 项目将在 2027 年底前被取消 A。这是「部署狂热 + 治理真空 + 标准真空」同时存在的窗口——对范式级项目是机会，对融资是坏时机。

愿景结论

C1 与 C2 被 2026 年的量化证据强力验证；C3 部分被削弱；「容器」定位是真实独占空白

C1 是本次调研中证据最硬的一条。长周期失败已被精确量化：Long-Horizon-Terminal-Bench 上 15 个前沿模型最佳 pass@1 仅 15.2%、均值 4.3%（单任务平均 990 万 token / 231 episode / 85.3 分钟）S+A；OSWorld 2.0 上顶级 agent 二元完成率 20.6%，超过 163 分钟的任务全线 0% A；SciAgentArena 发现 agent 在需要「真正新颖洞察」与「自主探索」的任务上系统性乏力，且方法选择高度保守 S。「agent 不知道自己不知道什么」从哲学论断变成了可测量的悬崖。

C2 的方向已被行业验证，抽象未被验证。「RAG → context engineering → context layer」的迁移已发生（纯长上下文路线企业采用率 30 天内从 15.5% 崩到 3.5%A；Gartner 预测 2028 年 >50% agent 系统将用 context graph A）。但没有人在做「切片」这种无 schema、可子类化的自由容器——Letta 的 memory block 是 typed，LangGraph state 是 TypedDict，Zep 是固定图 schema。这是真实的独占空白，也是真实的工程负债。

「agent 是居民、不是使用者」的容器定位，在整个业界找不到对应物。现有的多 agent 平台（A3 / HiClaw / Multica / Fastio）都是「任务队列 + 协作层」，没有一个是「有内部构造、可嵌套、agent 栖息其中」的容器 A+B。

✗ 证伪优先 · C3「编排」被削弱的部分

04 文档把候选机制定为「切片作为执行单元的有向依赖图 + 调度事件协议」，并警示「必须说清与 LangGraph 等现有编排框架的差异」。调研结果：LangGraph 早就不是静态图——ServerRuntime 工厂函数每次运行重建图、Command 让节点自行决定跳转、动态 add_node 是官方支持的模式（官方文档明确列举「实现递归或自修改 agent」为用例）。

剩下的真实差异只有一条：可变性的主体。LangGraph 的运行时变化由开发者代码参数化；Sponge 主张由 agent 改写。这是「谁有写权限」的差异，不是「图能不能变」的差异。C3 必须按这条重写，否则一碰就碎。

◆ 治理的收敛答案：隔离优先于智能

所有可靠方案给出的答案是同一个：把「可变的策略」与「不可变的记录」在架构上分开，而不是让 agent 更聪明。EXO 的类比最精确——executor 是应用程序，exoharness 是 append-only 事务日志；agent 的身份住在日志里，不住在代码里。

治理清单（可直接抄进 Sponge 的契约）：① 枚举可编辑面，面外即不可变；② 每次自编辑携带变更契约（目标组件 / 预测效果+置信区间 / 证伪测试 / 回滚计划 / 到期自动回滚）；③ 三轨晋升（auto / human-gated / hard-blocked），hard-blocked 在 agent 之外强制；④ 影子验证（真实流量上对比分布，固定基底以确保测得的是变更而非漂移）；⑤ 不变量与成功指标放在 agent 无法触及的签名存储；⑥ 递归底线——优化器永不能编辑自己的治理、不变量、变更契约检查器、指标存储，且必须用 capability-based security 在架构层强制，而非由被编辑的 harness 自我约束 A。

对 Sponge 的直接含义：04 三节把「固定层 vs 演化层」表述为「契约文档明确什么不可变」。按业界证据，文档级保护（Ouroboros 的 BIBLE.md）弱于架构级保护（EXO 的 exoharness）。Sponge 的固定层必须是 agent 代码不可达的 capability 边界，不能只是「文档说不能改」。

⚠ 自演化的已知失败模式（坟场证据）

① 执行偏置（execution bias）：Zhao et al.（Findings of ACL 2026）证明，从完全良性任务中积累的经验，会在 agent 遭遇高风险场景时损害安全性——经验强化了「行动」倾向，削弱了拒绝能力 A。这直接威胁 AgentPark 的「经验驱动演化」。

② 分布崩塌：Evo-Bench 测得自改进脚手架最高 +16.6 分，但在 prescribed-workflow 任务上崩塌 A。演化不是普适增益。

③ 回滚不回滚世界：EXO 的 fork/rewind 能反转状态，但反转不了已发出的邮件、已开的 PR、已扣的款。「每一次持久状态设计都有这条接缝，真实风险就集中在这里」A。

④ 环境重写攻击：OpenART 发现，重写 agent 的环境而非其提示词，能让已上线的 agent 85% 失效，且运行时本身解释了攻击是否奏效的方差 A。对「结构即数据」的 Sponge，这是最高相关的安全发现。

⑤ 归因天花板：LongRCA Bench（1,140 条真实失败轨迹，中位 145 步）上最强基线的精确根因步准确率仅 13.2%，作者方法 RCTA 也只到 24.1% S。演化依赖正确归因，而归因能力目前有硬天花板。

4.2 定位图：空白 / 盲区 / 坟场

◆ Sponge 独占的空白（业界真的没人做）

① 容器本体论。「agent 是居民、不是使用者；抽象类是内部构造、不是分类学；容器可嵌套」——所有多 agent 平台（A3 / HiClaw / Multica / Fastio）都是任务队列与协作层，没有一个把「空间」当本体。这是最强的独占空白。

② 中央调度三合一。编排 + 主动释放 + 演化放进同一个闭环、共用同一份结构化状态、且调度器自身可替换。组合独占，非机制独占。

③ 自由容器抽象。无 schema、可子类化的状态容器。所有记忆层都 typed，Sponge 是唯一的 untyped 提案。

④ 域作为独立的权限/能动性轴。业界有权限分层（DeepSeek Harness 四级权限、Copilot Studio 治理、EU AI Act 风险分级），但都是静态的、按资源划分的。Sponge 的「确定 / 待进化 / 主体」是按实体存在模式划分、且可迁移的——迁移即演化的「封版」动作。这个设计未检索到对应物。

⚠ Sponge 的盲区（大家在做，Sponge 文档里没提）

① 协议与互操作 —— 入场券问题。00–07 与契约文档里没有 MCP / A2A / Agent Plugins 的位置。2026-08 的现实是：连接层（MCP）、能力层（Agent Skills）、打包层（Agent Plugins）都已标准化。不兼容即自建孤岛。

② 评测基础设施。Sponge 有 context-recovery cost 北极星指标与证伪条件，但没提接入现成的长周期基准（Long-Horizon-Terminal-Bench / OSWorld 2.0 / SciAgentArena / LongRCA）。这些基准已经把 C1 的失效域量化好了，自建基准是重复投资。

③ 身份、委派链与中途撤销。D-J 把主体定案为域形式并先落 owner + role 字段。但 2026 的 agent 治理主线是 identity + delegation chain + revocation：EU AI Act Art.12 要求「技术上允许自动记录事件」，Art.14 要求停止按钮，Okta/Descope 的落点是「每个 agent 独立 OAuth Client ID + 委派链 + 可即时撤销的短时效凭证」。递归委派会在每一跳放大权限而不收窄——Sponge 的 authority 字段目前覆盖不到这一点。

④ 成本模型。长周期任务的真实约束是钱：单任务 990 万 token。Sponge 的注意力语义有 budget，但缺系统级的成本模型与预算治理。

⑤ 失败归因。演化需要归因作为输入，而 LongRCA 证明 145 步轨迹的精确根因定位只有 13.2%。Sponge 谈「演化」却没谈「演化依据什么信号」——这是演化机制能否落地的硬前提。

⑥ 状态卫生。C2 假设外部化 + 结构化就解决了上下文问题。但结构化状态自身会腐化：冲突、陈旧、冗余。Sponge 的切片契约里没有遗忘、冲突消解、陈旧检测的设计（信息源接口只有 traverse / impact / path）。

✗ 坟场：试过且失败的（先发 ≠ 有效，放弃 ≠ 错误）

框架层：AutoGen（2023-10 首发，50k+ stars，2026-04 被 Microsoft Agent Framework 吸收，转维护模式）；Flowise（被 Workday 收购，退出独立赛道）；Langflow（被 DataStax 收购，<1.7.1 有严重 CVE 含 .env 处理漏洞）。

技术路线层：纯长上下文路线（企业采用率 30 天内 15.5% → 3.5%）；RAG 作为完整策略（被 context architecture 取代，RAG 降级为其中一层检索原语）；prompt-as-config（system prompt 占 69% 输入 token 后崩塌）。

项目层：Gartner 预测 >40% agentic 项目 2027 年底前取消；试点 65% vs 生产 11% 的死亡谷；agent washing（数千家自称，约 130 家为真）。

自演化层：execution bias（良性经验损害安全性）；Evo-Bench 在 prescribed-workflow 任务上崩塌；OpenART 环境重写让已上线 agent 85% 失效；回滚不回滚世界。

4.3 时机与风险

时机窗口：开着

  • 治理真空。80% 企业已部署、仅 21% 有成熟治理模型。Sponge 的域 / authority 若做对，正对一个真空。
  • 信任层未标准化。协议与格式已定，信任与分发未定——空白仍在。
  • 长周期失败已被量化。C1 不需要再论证，只需要被解决。
  • 宿主刚出现。DeepSeek Harness（2026-08-13）刚开源，Editor/Portal 的搭车窗口在最初 6–12 个月。
  • 资本正在转向编排层。Q2 agentic 相关占 AI 融资 47%。

风险清单

  • 融资窗口极窄（最高）。2026 Q1 全球新成立 agentic 创业公司仅 1 家。若依赖外部早期融资，几乎不可能；内部研究可控。
  • 归因天花板。13.2% 的根因定位准确率意味着演化缺乏可靠输入信号。
  • 标准分裂。Anthropic 缺席 Agent Plugins TSC；MCP v1.0 RC 去会话化大改。押错版本代价高。
  • 自由容器的可验证性。无 schema = 无法校验/索引/迁移。通用性优势即工程负债。
  • 自演化安全性已被部分证伪。execution bias 与 85% 环境重写攻破率直接威胁 AgentPark。
  • 画布层红海化。Dify/Langflow/n8n 合计 45 万+ stars，Editor 若以画布为卖点必败。

建议 01 · 最高优先级 · 服务 P0-2 与 04 第四节

把 C3 从「三个动词」改写为「一个可替换的调度闭环 + 一条架构级递归底线」

为什么：调研证明三者的机制对应物在业界全都存在（LangGraph ServerRuntime / ProAct / self-evolving taxonomy）。Sponge 打不赢机制独占；组合与耦合是唯一能守的阵地。同时，04 三节把固定层表述为「契约文档明确什么不可变」——按业界证据，文档级保护（Ouroboros 的 BIBLE.md）弱于架构级保护（EXO 的 exoharness）。
  • 改写 C3：「护城河 = 编排 / 主动释放 / 演化共用同一份结构化状态，由同一个可替换内核驱动，且内核自身是 C4 意义上的可替换零部件。」这让 C3 与 C4 咬合，而不是两个孤立主张。
  • 硬线的实现方式：固定层 = agent 代码在架构上不可达的 capability 边界（事件日志、密钥、快照、不变量、变更契约检查器、指标存储），而非「文档说不能改」。直接采用 EXO 的三分：executor（可丢弃） / exoharness（不可达） / sandbox（副作用）。
  • 演化的触发器与规则：照抄变更契约六件套——目标组件 / 预测效果 + 置信区间 / 证伪测试（什么不能回退、回退多少）/ 回滚计划 / 到期自动回滚 / 三轨晋升（auto、human-gated、hard-blocked，hard-blocked 在 agent 之外强制）。这条直接回答 04 四节第 3 问「演化必须落到具体触发器与规则」。
  • 影子验证：任何结构变更在真实流量上影子运行、对比行为分布，且跑在固定基底上，确保测得的是变更而非漂移。

建议 02 · 服务 P0-1 通道形式化

把通道定义为「受 schema 约束的图重写原语」，直接对齐 arXiv:2608.18104

为什么：通道是 P0 阻塞项，04 六节给了三个候选定义无法抉择。而 2026-06 的 Self-Evolving Agents as Dynamic Graph Transformation（UNSW / UTS / CUHK-Shenzhen / 浙工商）几乎就是「切片 + 通道」的学术镜像：把 agent 状态建模为带类型节点、边、子图的动态图，通过受 schema 约束的重写（schema-constrained rewrites）更新，并给出四分类——node/feature 演化、edge/topology 演化、subgraph activation、跨组件共演化。
  • 通道 = 一组 rewrite rule（add/remove/retype node、add/remove edge、activate/deactivate subgraph），每条 rule 带 precondition + postcondition + rollback。
  • 这个定义直接解掉 04 六节的二选一：通道 = 切片间连接（静态面）= edge/topology rewrite；通道 = 系统改造机制（动态面）= schema 变更 rewrite。两者是同一组原语的两种应用，不是两个候选定义。
  • 规则本身属于固定层（agent 不能发明新 rule）；规则的内容（哪个切片在何种条件下可触发哪条 rule）属于演化层。这同时把「域」落到了实处：待进化域 = 该切片可自由触发 rule；确定域 = 触发需审批；主体域 = 可主动发起 rule。
  • 白拿的收益：该 survey 还给出 5 类 graph-aware 评估与治理协议（补端到端任务指标的不足），可直接作为 Sponge 演化的验收标准。

建议 03 · 服务 01 六节可证伪性

C1 的证伪实验不要自建基准，直接挂到 Long-Horizon-Terminal-Bench / OSWorld 2.0 / SciAgentArena 上

为什么：C1 的失效域已经被这三个基准精确量化（15.2% / 20.6% / 0%>163min）。对比基线是现成的、公开的、可复现的。自建基准是重复投资，且拿不到社区可比性。更关键的是 arXiv:2607.27283 的 horizon residual 方法论已经把「任务大」与「轨迹诱导退化（context rot）」区分开——这正是 C1 需要的分离变量工具。
  • 北极星指标重新定义：把 context-recovery cost 具体化为「在任务进行到 X% 时强制销毁全部上下文，测量恢复到同等进度所需的 token 数与步数」。对照组是同一任务不间断运行的基线。
  • 这个指标不需要 Sponge 完整实现：只要「切片 + 信息源」的最小闭环就能跑。这是收敛设计里最值钱的一点——C1 和 C3 的检验可以提前到 MVP 之前。
  • C3 的对照实验（01 六节：纯脚手架 + 好 prompt vs Sponge 调度系统）挂在同一批任务上，用 horizon residual 作分离指标。若 residual 无显著差异，C3 被削弱——这个判据现在有公开的测量方法了。
  • 不要引用厂商基准（Mem0 的 LongMemEval 一个来源报 49.0%、一个报 94.4）。自建 golden set。

建议 04 · 服务 07 九节待裁决项 2 与 3

Editor MVP 跳过画布：顺序改为 S1′（兼容信封的文件级）→ S3（agent 工具面）→ S2（画布）

为什么：07 规划是 S1 文件级 → S2 画布 → S3 agent 工具面 → S4 集成，并自陈「10k 行预算的压力主要在编辑器」「画布是目的地，文件级只是它的脚手架」。但调研显示两件事：① 画布层是绝对红海（Dify 133k + Langflow 146k + n8n 176k stars，加 Copilot Studio / Vertex AI / watsonx 三家巨头）；② 权力转移（野心一）的验收点是 S3，不是 S2——画布只是人机界面，agent 工具面才是「agent 改自己的结构」。
  • S1′：把 pipeline 落成 Agent Plugins 1.0 兼容的目录格式——plugin.json 信封（标准化）+ Sponge 私有的 slices/ 目录（内容私有）。该规范明确只管打包、不管语义，这恰好是 Sponge 需要的分工。收益：借分发与客户端生态、不自建孤岛、满足「结构即数据、可 diff、可版本化」。
  • S3 提前：先用最小代价验证「agent 能否用工具面改造自己的结构」——这才是野心一的验收。07 七节的「双面同构」（人类 UI 与 agent 工具面共用同一结构、能力对称）本身就是最难的工程，早做早暴露。
  • S2 后移：画布是「操作简单」的兑现（07 八节：画布是目的地），但它不是范式验收点，且竞争最激烈。放到 S3 闭环跑通之后。
  • 调度器开发位置（待裁决项 3）：建议独立模块、独立仓。理由：C3 已改写为「调度器自身可替换」，那么它在物理上就该是可替换的——做成 Harness 内的包会与「护城河独立性优先」自相矛盾。

建议 05 · 补盲区 · 服务 D-J 与 C2

补上三块缺失设计：identity/委派链、失败归因、状态卫生

为什么：这三块是「大家在做、Sponge 没提」的盲区，且都直接威胁 Sponge 的核心主张。缺了它们，演化没有输入信号、多主体不可部署、结构化状态会自己腐化。
  • identity 与委派链（威胁 C5 与多主体）。D-J 定案「MVP 先落 owner + role 字段」，但 2026 的治理主线是「每个 agent 独立身份 + 委派链 + 可即时撤销」：递归委派会在每一跳放大权限而不收窄；EU AI Act Art.12 要求技术上可自动记录、Art.14 要求停止按钮；Okta 指出「长时效不可撤销的 token 不是停止按钮，只是一个请求」。最小落点：authority 字段扩为 (subject, delegate_of, scopes, issued_at, expires_at, revocable)。
  • 失败归因（威胁演化）。LongRCA 证明 145 步轨迹的精确根因定位仅 13.2%，责任角色定位 51.1%——二者相差 2 倍以上，说明「谁错了」和「哪一步错了」是难度不同的两个问题。演化依赖后者。最小落点：切片的每次状态迁移记录 (trigger, before, after, actor)，粒度对齐 LongRCA 的「earliest decisive root-cause step」。这也顺带回答 04 四节第 3 问的「什么事件触发」。
  • 状态卫生（威胁 C2）。C2 隐含假设「外部化 + 结构化即解决」，但结构化状态自身会腐化。工程界已给出的三条处方（把状态当受管数据、按时间轴设检查点、提交前强制验证）都是补丁而非机制。最小落点：信息源接口在 traverse / impact / path 之外，把 conflict 与 decay 提到接口层（而非留在 Statuz 实现层）——同时满足 04 五节「接口不得出现 Statuz 专属概念」的验收标准，并让「遗忘」成为 C2 的一等公民（01 三节呼吁的「状态、经验、演化、遗忘」四件套，目前只覆盖了前三个）。
